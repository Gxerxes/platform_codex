# ADR-0002：Palette BFF 职责边界

## 状态

已采纳，待业务与安全评审确认。

## 背景

企业应用需要统一处理浏览器认证、服务端会话、令牌、受控下游访问和平台能力。直接分散到业务应用会造成重复实现和安全不一致。

## 决策

Palette BFF 定位为浏览器和企业身份基础设施之间的受控交互层，负责：

- OIDC 登录与企业身份集成。
- 服务端会话和令牌生命周期。
- 安全 Cookie 与 CSRF。
- 受控下游代理与 Token Relay。
- 应用级认证和授权。
- 统一错误、日志、指标和审计。

BFF 不承载核心业务领域逻辑，不替代 API Gateway，不接受任意代理目标地址。

## 可选方案

### 直接由前端调用下游

优点：架构简单。

缺点：敏感令牌暴露、会话和认证逻辑分散、不利于统一安全边界，不采纳。

### BFF 承载完整业务领域

优点：业务改造成本短期低。

缺点：形成业务整体平台耦合、回归 API Gateway 职责、不利于复用，不采纳。

### BFF 与 API Gateway 合并

优点：组件较少。

缺点：企业网关职责无法确认，且可能形成部署和治理耦合，暂不采纳。

## 后果

- 业务领域逻辑保持在下游业务服务。
- 下游地址与路由必须受配置注册表约束。
- 后端权限校验不能由前端替代。
- 企业网关继续负责企业级流量、安全和治理能力。
