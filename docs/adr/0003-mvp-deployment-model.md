# ADR-0003：MVP 部署与 Session 模型

## 状态

建议采用；生产存储由企业基础设施确认。

## 背景

Palette BFF 需要在保证安全的同时支持业务应用接入。MVP 阶段不应过早引入复杂分布式基础设施，但生产部署可能要求水平扩展。

## 决策

- MVP 应构建为可水平部署的 Spring Boot 单应用。
- 支持可配置的本地与集中式 Session 策略；MVP 先不绑定未确认的 Redis 架构。
- 分布式环境下优先评估 Spring Session 与企业批准的 Session Store。
- 初始采用公共共享 BFF 实例，只有强隔离场景才部署专用实例。
- 部署拓扑、域名、SSL 终止、代理信任和 Cookie 规则由企业基础设施确认。

## 可选方案

### 单实例 Sticky Session

优点：实施简单。

缺点：实例故障、弹性伸缩和滚动发布受限，不适合作为长期生产策略。

### Redis 集中式 Session

优点：可水平扩展，故障恢复能力较好。

缺点：增加 Redis 可用性、网络、容量和密钥治理成本。

### 平台提供的托管 Session

优点：可降低运维负担。

缺点：必须确认企业平台能力和兼容性；目前无可靠接口信息，不能在 Step 0 虚构。

## 后果

- Step 5 前不得假设 Redis 已存在。
- Session 抽象应使用 Spring 原生能力与可配置存储。
- 部署清单需明确实例数、可用区、健康检查和重启影响。
